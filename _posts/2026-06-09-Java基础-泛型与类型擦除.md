<th>使用泛型后</th> </tr> </thead> <tbody> <tr> <td><code>List list = new ArrayList();</code><br> <code>list.add("hello");</code><br> <code>String s = (String) list.get(0);</code> // 需要强转</td>  <p>上图展示了泛型的核心思想——类型参数化。传统方式需要为每种类型单独定义一个类，导致大量重复代码；而泛型将类型作为参数传入，实现了一套代码适用于多种类型。</p> <ul> <li><strong>类型参数</strong> ：如 <code>&lt;E&gt;</code> 、 <code>&lt;T&gt;</code> 、 <code>&lt;K, V&gt;</code> 等，在定义时是占位符，在使用时被具体类型替换。</li> <li><strong>泛型类</strong> ：类名后跟类型参数，如 <code>ArrayList&lt;E&gt;</code> 。</li> <li><strong>泛型接口</strong> ：接口名后跟类型参数，如 <code>Comparable&lt;T&gt;</code> 。</li> <li><strong>泛型方法</strong> ：方法返回值前声明类型参数，如 <code>&lt;T&gt; T getFirst(List&lt;T&gt; list)</code> 。</li> </ul> <H3>二、泛型的三种使用方式</H3> <p><strong>1. 泛型类</strong></p> <pre><code class="language-java" data-lang="java">// 自定义泛型类
public class Box&lt;T&gt; {
    private T content;

    public void set(T content) {
        this.content = content;
    }

    public T get() {
        return content;
    }
}

// 使用
Box&lt;String&gt; stringBox = new Box&lt;&gt;();
stringBox.set("Hello");
String value = stringBox.get();  // 无需强转

Box&lt;Integer&gt; intBox = new Box&lt;&gt;();
intBox.set(123);
Integer num = intBox.get();</code></pre> <p><strong>2. 泛型接口</strong></p> <pre><code class="language-java" data-lang="java">// 泛型接口
public interface Generator&lt;T&gt; {
    T generate();
}

// 实现方式一：指定具体类型
public class StringGenerator implements Generator&lt;String&gt; {
    @Override
    public String generate() {
        return "Hello";
    }
}

// 实现方式二：保留泛型
public class GenericGenerator&lt;T&gt; implements Generator&lt;T&gt; {
    @Override
    public T generate() {
        return null;
    }
}</code></pre> <p><strong>3. 泛型方法</strong></p> <pre><code class="language-java" data-lang="java">public class GenericMethodDemo {

    // 泛型方法：&lt;T&gt; 声明在返回值前
    public static &lt;T&gt; T getFirst(List&lt;T&gt; list) {
        if (list == null || list.isEmpty()) {
            return null;
        }
        return list.get(0);
    }

    // 多个类型参数
    public static &lt;K, V&gt; void printPair(K key, V value) {
        System.out.println(key + " = " + value);
    }

    // 使用
    public static void main(String[] args) {
        List&lt;String&gt; names = Arrays.asList("张三", "李四", "王五");
        String first = getFirst(names);  // 编译器自动推断类型

        printPair("name", "张三");
        printPair(1, 100);
    }
}</code></pre> <H3>三、泛型的核心原理：类型擦除</H3>   <p>上图展示了 Java 泛型的核心机制——类型擦除。这是理解泛型的关键。</p> <ul> <li> <p><strong>擦除时机</strong> ：编译期间，编译器将泛型类型替换为原始类型（Raw Type）或上界。</p> </li> <li> <p><strong>擦除规则</strong> ：</p> <ul> <li>无限界类型参数 <code>&lt;T&gt;</code> 擦除为 <code>Object</code></li> <li>有上界 <code>&lt;T extends Number&gt;</code> 擦除为 <code>Number</code></li> <li>多个上界 <code>&lt;T extends Serializable &amp; Cloneable&gt;</code> 擦除为第一个上界</li> </ul> </li> <li> <p><strong>运行时表现</strong> ：</p> <pre><code class="language-java" data-lang="java">List&lt;String&gt; strings = new ArrayList&lt;&gt;();
List&lt;Integer&gt; integers = new ArrayList&lt;&gt;();

// 运行时返回 true！（类型信息被擦除）
System.out.println(strings.getClass() == integers.getClass());</code></pre> </li> </ul> <p><strong>类型擦除的代码对比：</strong></p> <pre><code class="language-java" data-lang="java">// 源代码
public class Box&lt;T&gt; {
    private T value;

    public T get() { return value; }
    public void set(T value) { this.value = value; }
}

// 编译后（反编译结果）
public class Box {
    private Object value;           // T → Object

    public Object get() { return value; }
    public void set(Object value) { this.value = value; }
}</code></pre> <H3>四、通配符详解</H3>   <p>上图对比了三种通配符的特点和使用场景，核心原则是 <strong>PECS</strong> （Producer Extends, Consumer Super）。</p> <p><strong>PECS 原则详解：</strong></p> <pre><code class="language-java" data-lang="java">public class PECSDemo {

    // Producer Extends：从集合读取数据（生产者）
    public static double sum(List&lt;? extends Number&gt; list) {
        double total = 0;
        for (Number num : list) {  // 可以安全读取为 Number
            total += num.doubleValue();
        }
        // list.add(123);  // 编译错误！不能写
        return total;
    }

    // Consumer Super：向集合写入数据（消费者）
    public static void addNumbers(List&lt;? super Integer&gt; list) {
        list.add(1);   // 可以安全写入 Integer
        list.add(2);
        list.add(3);
        // Integer i = list.get(0);  // 编译错误！不能读为 Integer
    }

    public static void main(String[] args) {
        List&lt;Integer&gt; integers = Arrays.asList(1, 2, 3);
        List&lt;Double&gt; doubles = Arrays.asList(1.1, 2.2, 3.3);

        System.out.println(sum(integers));  // 6.0
        System.out.println(sum(doubles));   // 6.6

        List&lt;Number&gt; numbers = new ArrayList&lt;&gt;();
        addNumbers(numbers);  // 可以写入 Integer
    }
}</code></pre> <H3>五、泛型的限制</H3> <p>由于类型擦除，泛型有以下限制：</p> <pre><code class="language-java" data-lang="java">public class GenericLimitations&lt;T&gt; {

    // ❌ 1. 不能用基本类型作为类型参数
    // List&lt;int&gt; list;  // 编译错误
    List&lt;Integer&gt; list;  // 必须使用包装类

    // ❌ 2. 运行时类型检查只适用于原始类型
    // if (list instanceof List&lt;String&gt;) {}  // 编译错误
    if (list instanceof List) {}  // 只能检查原始类型

    // ❌ 3. 不能创建泛型数组
    // T[] array = new T[10];  // 编译错误
    T[] array = (T[]) new Object[10];  // 只能通过强转

    // ❌ 4. 不能实例化类型参数
    // T obj = new T();  // 编译错误
    T obj = (T) new Object();  // 只能通过强转

    // ❌ 5. 不能创建泛型静态字段
    // private static T staticField;  // 编译错误

    // ❌ 6. 泛型类不能继承 Throwable
    // class MyException&lt;T&gt; extends Exception {}  // 编译错误
}</code></pre> <H3>六、泛型 vs Object 对比</H3> <table> <thead> <tr> <th>对比维度</th> <th>使用 Object</th> <th>使用泛型</th> </tr> </thead> <tbody> <tr> <td>类型安全</td> <td>运行时才能发现类型错误</td> <td>编译期就能发现类型错误</td> </tr> <tr> <td>强制转换</td> <td>必须手动强转</td> <td>编译器自动插入强转</td> </tr> <tr> <td>代码可读性</td> <td>需要查看文档才知道类型</td> <td>类型信息直观可见</td> </tr> <tr> <td>性能</td> <td>有装箱拆箱开销</td> <td>基本类型需包装，但无额外开销</td> </tr> <tr> <td>灵活性</td> <td>灵活但不安全</td> <td>安全且灵活</td> </tr> </tbody> </table> <pre><code class="language-java" data-lang="java">// Object 方式
List list1 = new ArrayList();
list1.add("hello");
list1.add(123);  // 编译通过
String s = (String) list1.get(0);  // 需要强转

// 泛型方式
List&lt;String&gt; list2 = new ArrayList&lt;&gt;();
list2.add("hello");
// list2.add(123);  // 编译错误！
String s2 = list2.get(0);  // 无需强转</code></pre> <H2>面试高频追问</H2> <ol> <li> <p><strong>什么是类型擦除？为什么 Java 要这样设计？</strong></p> <p>类型擦除是编译器在编译时将泛型类型替换为原始类型或上界的过程。Java 这样设计是为了 <strong>向后兼容</strong> ，确保 JDK 5 之前的代码在新版本中仍能运行，这是 Java 设计者的权衡之举。</p> </li> <li> <p><strong><code>List&lt;?&gt;</code> 、 <code>List&lt;Object&gt;</code> 和 <code>List</code> 有什么区别？</strong></p> <ul> <li><code>List&lt;?&gt;</code> ：未知类型的 List，只能读不能写（类型安全）</li> <li><code>List&lt;Object&gt;</code> ：元素类型为 Object 的 List，可以读写任意对象</li> <li><code>List</code> ：原始类型，绕过泛型检查，不推荐使用</li> </ul> </li> <li> <p><strong>泛型数组为什么不能创建？</strong></p> <p>因为类型擦除后， <code>List&lt;String&gt;[]</code> 和 <code>List&lt;Integer&gt;[]</code> 都变成 <code>List[]</code> ，如果允许创建，会导致类型安全问题。</p> </li> </ol> <H2>常见面试变体</H2> <ul> <li>"Java 泛型是如何实现的？和 C++ 模板有什么区别？"</li> <li>"什么是 PECS 原则？能举个例子吗？"</li> <li>"泛型的类型擦除会带来什么问题？如何解决？"</li> <li>"如何实现一个泛型数组？"</li> </ul> <H2>记忆口诀</H2> <p><strong>泛型本质</strong> ：类型参数化，编译期检查。</p> <p><strong>PECS 原则</strong> ：生产者用 <code>extends</code> （只读），消费者用 <code>super</code> （只写）。</p> <p><strong>类型擦除</strong> ：编译时擦除为 <code>Object</code> 或上界，运行时无泛型信息。</p> <H2>总结</H2> <p>Java 泛型通过类型参数化实现编译期类型检查，解决了类型安全和强制转换问题。核心原理是类型擦除——编译时将泛型类型替换为原始类型，这是 Java 为了向后兼容的设计权衡。使用时遵循 PECS 原则（Producer Extends, Consumer Super），并注意泛型的限制（不能用基本类型、不能创建泛型数组等）。</p> </div></main>
