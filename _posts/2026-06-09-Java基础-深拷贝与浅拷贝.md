对象在内存中的存储结构，以及引用类型和基本类型的区别。</p> </li> <li> <p><strong>实现方式掌握</strong> ：考察你是否知道如何实现深拷贝（ <code>Cloneable</code> 、序列化、第三方工具），以及各种方式的优缺点。</p> </li> <li> <p><strong>实战经验</strong> ：实际开发中何时需要深拷贝？哪些场景下浅拷贝会导致 </thead> <tbody> <tr> <td>对象本身</td> <td>✅ 复制</td> <td>✅ 复制</td> </tr> <tr> <td>基本类型成员</td> <td>✅ 复制值</td> <td>✅ 复制值</td> </tr> <tr> <td>引用类型成员</td> <td>❌ 只复制引用（共享）</td> <td>✅ 递归复制对象</td> </tr> <tr> <p>上图清晰展示了浅拷贝和深拷贝在内存中的区别。关键要点：</p> <ul> <li> <p><strong>浅拷贝的 "坑"</strong> ：虽然 <code>Person</code> 对象复制了一份，但 <code>address</code> 引用指向的是 <strong>同一个 <code>Address</code> 对象</strong> 。修改拷贝对象的地址，原对象的地址也会跟着变。</p> </li> <li> <p><strong>深拷贝的 "彻底"</strong> ：不仅复制 <code>Person</code> ，连 <code>Address</code> 对象也一起复制，两个对象完全独立，互不影响。</p> </li> </ul> <H3>二、代码示例：浅拷贝翻车现场</H3> <pre><code class="language-java" data-lang="java">// 地址类（引用类型成员）
class Address implements Cloneable {
    String city;

    public Address(String city) {
        this.city = city;
    }

    @Override
    protected Address clone() throws CloneNotSupportedException {
        return (Address) super.clone();
    }
}

// 人员类
class Person implements Cloneable {
    String name;
    int age;           // 基本类型
    Address address;   // 引用类型

    public Person(String name, int age, Address address) {
        this.name = name;
        this.age = age;
        this.address = address;
    }

    @Override
    protected Person clone() throws CloneNotSupportedException {
        return (Person) super.clone();  // 浅拷贝：只复制当前对象
    }
}

// 测试浅拷贝的问题
public class ShallowCopyDemo {
    public static void main(String[] args) throws Exception {
        Person original = new Person("张三", 25, new Address("北京"));

        // 浅拷贝
        Person copy = original.clone();

        // 修改拷贝对象的基本类型：不影响原对象
        copy.age = 30;
        System.out.println(original.age);  // 输出: 25（未受影响）

        // 修改拷贝对象的引用类型：原对象也被修改了！
        copy.address.city = "上海";
        System.out.println(original.address.city);  // 输出: 上海（被影响了！）
    }
}</code></pre> <p>看到了吗？修改 <code>copy.address.city</code> 后， <code>original.address.city</code> 也变成了 "上海"，这就是浅拷贝的 "坑"。</p> <H3>三、深拷贝的三种实现方式</H3> <H4>方式一：递归调用 clone()（手动实现）</H4> <pre><code class="language-java" data-lang="java">class Person implements Cloneable {
    String name;
    int age;
    Address address;

    @Override
    protected Person clone() throws CloneNotSupportedException {
        Person cloned = (Person) super.clone();
        cloned.address = address.clone();  // 递归克隆引用类型
        return cloned;
    }
}

// Address 也必须实现 Cloneable
class Address implements Cloneable {
    String city;

    @Override
    protected Address clone() throws CloneNotSupportedException {
        return (Address) super.clone();
    }
}</code></pre> <p><strong>缺点</strong> ：如果对象层级很深，需要每层都实现 <code>Cloneable</code> 并重写 <code>clone()</code> ，代码冗余且容易遗漏。</p> <H4>方式二：序列化/反序列化（推荐）</H4> <pre><code class="language-java" data-lang="java">import java.io.*;

class Person implements Serializable {
    String name;
    int age;
    Address address;

    // 深拷贝方法
    public Person deepCopy() {
        try {
            // 序列化到字节流
            ByteArrayOutputStream bos = new ByteArrayOutputStream();
            ObjectOutputStream oos = new ObjectOutputStream(bos);
            oos.writeObject(this);

            // 从字节流反序列化
            ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
            ObjectInputStream ois = new ObjectInputStream(bis);
            return (Person) ois.readObject();
        } catch (Exception e) {
            throw new RuntimeException("深拷贝失败", e);
        }
    }
}

// 所有引用类型成员都必须实现 Serializable
class Address implements Serializable {
    String city;
}</code></pre> <p><strong>优点</strong> ：一行代码搞定，无需手动递归，支持任意深度的对象层级。</p> <p><strong>缺点</strong> ：性能相对较差，所有类必须实现 <code>Serializable</code> 。</p> <H4>方式三：第三方工具库（生产推荐）</H4> <pre><code class="language-java" data-lang="java">// 使用 Hutool 工具库
import cn.hutool.core.bean.BeanUtil;
import cn.hutool.core.clone.CloneSupport;

// 方式 1：BeanUtil 复制（浅拷贝，但可配置）
Person copy = BeanUtil.copyProperties(original, Person.class);

// 方式 2：JSON 序列化实现深拷贝
import com.fasterxml.jackson.databind.ObjectMapper;
ObjectMapper mapper = new ObjectMapper();
Person deepCopy = mapper.readValue(mapper.writeValueAsString(original), Person.class);

// 方式 3：Gson 实现深拷贝
import com.google.gson.Gson;
Gson gson = new Gson();
Person deepCopy = gson.fromJson(gson.toJson(original), Person.class);</code></pre> <p><strong>优点</strong> ：代码简洁，无需实现接口，性能和可维护性都较好。</p> <H3>四、三种方式对比</H3> <table> <thead> <tr> <th>实现方式</th> <th>代码复杂度</th> <th>性能</th> <th>适用场景</th> </tr> </thead> <tbody> <tr> <td>递归 <code>clone()</code></td> <td>高（每层都要实现）</td> <td>好</td> <td>对象层级浅且固定</td> </tr> <tr> <td>序列化/反序列化</td> <td>低（需 <code>Serializable</code> ）</td> <td>较差</td> <td>通用场景</td> </tr> <tr> <td>JSON 工具</td> <td>低（无需接口）</td> <td>中等</td> <td><strong>生产推荐</strong></td> </tr> </tbody> </table> <H2>面试高频追问</H2> <ol> <li> <p><strong>Java 的 <code>Object.clone()</code> 是浅拷贝还是深拷贝？</strong></p> <p>默认是 <strong>浅拷贝</strong> 。只复制当前对象的基本类型和引用，不会递归复制引用指向的对象。要实现深拷贝，需要在 <code>clone()</code> 方法中手动调用引用类型成员的 <code>clone()</code> 。</p> </li> <li> <p><strong>为什么 Java 设计成默认浅拷贝？</strong></p> <p>性能考虑。深拷贝需要递归复制整个对象图，如果对象层级很深或包含循环引用，可能导致性能问题或栈溢出。浅拷贝作为默认行为更安全、可控。</p> </li> <li> <p><strong>数组的 <code>clone()</code> 是深拷贝还是浅拷贝？</strong></p> <p>对于 <strong>基本类型数组</strong> 是深拷贝（值复制），对于 <strong>引用类型数组</strong> 是浅拷贝（引用复制）。</p> </li> </ol> <H2>常见面试变体</H2> <ul> <li>变体一："如何实现一个对象的深拷贝？"</li> <li>变体二：" <code>clone()</code> 方法为什么需要实现 <code>Cloneable</code> 接口？"</li> <li>变体三："序列化实现深拷贝的原理是什么？"</li> </ul> <H2>记忆口诀</H2> <p><strong>浅拷贝：壳子新，芯子旧，引用共享出 bug；</strong> <strong>深拷贝：里外新，彻底分，序列化来一键搞。</strong></p> <H2>总结</H2> <p>浅拷贝只复制对象本身，引用类型成员仍然共享；深拷贝递归复制所有层级对象，完全独立。生产环境推荐使用 JSON 工具（Jackson/Gson）或序列化方式实现深拷贝，避免手动递归 <code>clone()</code> 的繁琐和遗漏。</p> </div></main>
