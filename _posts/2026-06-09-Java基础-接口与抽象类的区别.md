"契约" 与 "模板" 的不同定位。</p> </li> <li> <p><strong>设计能力考察</strong> ：通过这个问题，面试官想评估你的面向对象设计思维，能否根据实际场景做出合理的抽象选择，而不是滥用继承或接口。</p> </li> <li> <p><strong>版本演进意识</strong> ：JDK 8 之后接口引入了默认方法和静态方法，这让接口和抽象类的界限变得模糊，考察你是否跟上 Java 的演进，以及在新特性下的选择逻辑。</p> </li> </ol> <H2>核心答案</H2> <p><strong>一句话总结</strong> ：接口定义 "能做什么"（行为契约），抽象类定义 "是什么"（本质模板）。</p> <H3>核心区别对比</H3> <table> <thead> <tr> <strong>设计意图</strong> ，用一个生活化的例子来理解：</p>   <p>上图展示了接口和抽象类的核心设计差异：</p> <ul> <li> <p><strong>接口（ <code>Flyable</code> ）</strong> ：定义的是 "飞行" 这个 <strong>能力/行为</strong> 。飞机、鸟、超人都可以飞行，但它们本质完全不同，没有共同的父类。接口强调的是 "能做什么"。</p> </li> <li> <p><strong>抽象类（ <code>Bird</code> ）</strong> ：定义的是 "鸟" 这个 <strong>本质/家族</strong> 。麻雀、老鹰、企鹅都是鸟，它们有共同的特征（羽毛、翅膀、产卵等）和可以复用的代码。抽象类强调的是 "是什么"。</p> </li> </ul> <p><strong>关键点</strong> ：企鹅虽然不会飞（不实现 <code>Flyable</code> ），但它依然是鸟（继承 <code>Bird</code> ）。这就是 "本质" 和 "能力" 的区别。</p> <H3>二、JDK 版本演进带来的变化</H3>   <p>上图展示了 Java 接口从 JDK 7 到 JDK 9+ 的演进过程：</p> <ul> <li> <p><strong>JDK 7 及之前</strong> ：接口是纯粹的抽象契约，只能包含抽象方法和常量，没有任何实现代码。</p> </li> <li> <p><strong>JDK 8</strong> ：引入 <code>default</code> 方法和 <code>static</code> 方法，允许接口提供默认实现。这是为了支持 API 演进，比如 <code>Collection</code> 接口新增 <code>forEach()</code> 、 <code>removeIf()</code> 等方法，已有的 <code>ArrayList</code> 、 <code>HashSet</code> 等实现类无需修改就能获得新功能。</p> </li> <li> <p><strong>JDK 9+</strong> ：进一步引入 <code>private</code> 方法，用于复用 <code>default</code> 方法中的公共代码逻辑，避免代码重复。</p> </li> </ul> <p><strong>面试加分点</strong> ：JDK 8 之后，接口和抽象类的界限确实变模糊了，但核心区别依然存在——接口不支持成员变量和构造方法，仍然是"轻量级"的行为规范。</p> <H3>三、代码示例对比</H3> <pre><code class="language-java" data-lang="java">// ==================== 接口定义 ====================
public interface Flyable {
    // 常量（自动 public static final）
    int MAX_SPEED = 1000;

    // 抽象方法（自动 public abstract）
    void fly();

    // JDK 8: 默认方法
    default void glide() {
        System.out.println("滑翔中...");
    }

    // JDK 8: 静态方法
    static void checkWeather() {
        System.out.println("检查天气状况");
    }
}

// ==================== 抽象类定义 ====================
public abstract class Animal {
    // 成员变量（可以有任何访问修饰符）
    protected String name;
    private int age;

    // 构造方法
    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // 具体方法（子类直接继承）
    public void eat() {
        System.out.println(name + " 正在进食");
    }

    // 抽象方法（子类必须实现）
    public abstract void makeSound();

    // 普通方法
    public int getAge() {
        return age;
    }
}

// ==================== 实际使用 ====================
// 飞机：实现 Flyable，继承 Object（默认）
public class Airplane implements Flyable {
    @Override
    public void fly() {
        System.out.println("飞机依靠引擎飞行");
    }
}

// 麻雀：继承 Bird（假设 extends Animal），实现 Flyable
public class Sparrow extends Animal implements Flyable {
    public Sparrow(String name, int age) {
        super(name, age);
    }

    @Override
    public void fly() {
        System.out.println(name + " 扇动翅膀飞行");
    }

    @Override
    public void makeSound() {
        System.out.println("叽叽喳喳");
    }
}</code></pre> <H3>四、选择决策流程</H3>   <p>上图展示了接口和抽象类的选择决策流程：</p> <ul> <li> <p><strong>第一步</strong> ：如果需要定义成员变量或构造方法，只能选择抽象类。这是接口无法提供的核心能力。</p> </li> <li> <p><strong>第二步</strong> ：如果需要多实现（一个类同时具备多种能力），必须选择接口。Java 不支持多继承，但支持多实现。</p> </li> <li> <p><strong>第三步</strong> ：如果以上条件都不满足，优先选择接口。接口更轻量、更灵活，符合"面向接口编程"的设计原则。</p> </li> </ul> <p><strong>典型应用场景</strong> ：</p> <ul> <li><strong>抽象类</strong> ：模板方法模式（如 <code>AbstractList</code> ）、共享代码和状态（如 <code>AbstractStringBuilder</code> ）</li> <li><strong>接口</strong> ：策略模式（如 <code>Comparator</code> ）、回调机制（如 <code>Runnable</code> 、 <code>Callable</code> ）、标记接口（如 <code>Serializable</code> ）</li> </ul> <H3>五、经典应用案例对比</H3> <pre><code class="language-java" data-lang="java">// ==================== 案例1: 抽象类 - 模板方法模式 ====================
// JDK 源码：java.util.AbstractList
public abstract class AbstractList&lt;E&gt; extends AbstractCollection&lt;E&gt; implements List&lt;E&gt; {
    // 提供基础实现，子类只需实现少量方法
    public E get(int index) {
        // 基于 iterator() 实现
    }

    public int indexOf(Object o) {
        // 提供通用实现
    }

    // 子类必须实现的核心方法
    public abstract E get(int index);
}

// ArrayList 只需实现少量方法，继承大量通用逻辑
public class ArrayList&lt;E&gt; extends AbstractList&lt;E&gt; {
    public E get(int index) {
        // 具体实现
    }
}

// ==================== 案例2: 接口 - 行为规范 ====================
// JDK 源码：Comparator 函数式接口
@FunctionalInterface
public interface Comparator&lt;T&gt; {
    int compare(T o1, T o2);

    // default 方法提供组合能力
    default Comparator&lt;T&gt; reversed() {
        return (o1, o2) -&gt; compare(o2, o1);
    }

    default Comparator&lt;T&gt; thenComparing(Comparator&lt;? super T&gt; other) {
        return (o1, o2) -&gt; {
            int res = compare(o1, o2);
            return (res != 0) ? res : other.compare(o1, o2);
        };
    }
}

// 使用：灵活组合多种比较策略
Comparator&lt;String&gt; comparator = Comparator
    .comparing(String::length)
    .thenComparing(String::compareTo);</code></pre> <H2>面试高频追问</H2> <ol> <li> <p><strong>JDK 8 之后接口可以有默认实现，那接口和抽象类还有什么区别？</strong></p> <p>核心区别依然存在：接口不能有成员变量（只能有常量）和构造方法，不支持状态维护；抽象类可以。接口强调"能力"，抽象类强调"本质"。</p> </li> <li> <p><strong>一个类可以同时继承抽象类和实现接口吗？</strong></p> <p>可以！而且这是常见的做法。比如 <code>ArrayList extends AbstractList implements List, RandomAccess, Cloneable, Serializable</code> 。</p> </li> <li> <p><strong>接口可以继承接口吗？抽象类可以实现接口吗？</strong></p> <p>接口可以多继承接口（ <code>interface A extends B, C</code> ）；抽象类可以实现接口（ <code>abstract class D implements A</code> ）。</p> </li> <li> <p><strong>什么时候用 default 方法，什么时候用抽象类？</strong></p> <p><code>default</code> 方法用于为已有接口添加新功能（向后兼容）；如果需要共享状态或复杂的模板逻辑，仍然应该使用抽象类。</p> </li> </ol> <H2>常见面试变体</H2> <ul> <li>"抽象类可以没有抽象方法吗？"（可以，比如 <code>AbstractStringBuilder</code> ）</li> <li>"接口可以继承抽象类吗？"（不可以，接口只能继承接口）</li> <li>"Java 为什么不支持多继承？"（菱形继承问题、复杂性、实际需求不大）</li> <li>"什么是函数式接口？和普通接口有什么区别？"（只有一个抽象方法的接口，可用 <code>@FunctionalInterface</code> 注解）</li> </ul> <H2>记忆口诀</H2> <pre><code class="language-groovy" data-lang="groovy">接口定义 "能做什么"（行为能力），抽象类定义 "是什么"（本质模板）；
接口可多实现，抽象类只能单继承；
接口是契约（轻量），抽象类是半成品（重量）；
需要状态/构造/成员变量 → 抽象类；
需要多实现/解耦/跨层次 → 接口。</code></pre> <H2>总结</H2> <p>接口和抽象类的核心区别在于 <strong>设计意图</strong> ：接口定义 "能力"（能做什么），抽象类定义 "本质"（是什么）。选择时，优先考虑是否需要成员变量/构造方法（用抽象类），是否需要多实现（用接口）。JDK 8 之后接口可以有默认实现，但无法改变"接口无状态"的本质，遵循"面向接口编程"原则， <strong>优先使用接口，必要时才用抽象类</strong> 。</p> </div></main>
