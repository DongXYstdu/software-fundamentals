并发事务之间的数据干扰，以及它们之间的本质区别。</p> </li> <li> <p><strong>隔离级别理解</strong> ：考察你是否清楚 MySQL 的四种事务隔离级别，以及每种隔离级别能解决哪些并发问题。</p> </li> <li> <p><strong>实践应用能力</strong> ：能否根据业务场景选择合适的隔离级别，是否了解 MVCC（多版本并发控制）如何解决这些问题。</p> </li> </ol> <H2>核心答案</H2> <p>脏读、不可重复读、幻读是 <strong>数据库并发事务</strong> 中三种典型的数据不一致问题：</p> <table> <thead> <tr> <th>问题</th> <th>定义</th> <th>关注点</th> <th>严重程度</th> </tr> </thead> <tbody> <tr> <td><strong>脏读</strong></td> <td>读到其他事务 <strong>未提交</strong> 的数据</td> <td>数据被回滚</td> <td>⭐⭐⭐ 最严重</td> </tr> <tr> <td><strong>不可重复读</strong></td> <td>同一事务内，两次读取 <strong>同一行</strong> 数据结果不同</td> <td>数据被修改/删除</td> <td>⭐⭐ 中等</td> </tr> <tr> <td><strong>幻读</strong></td> <td>同一事务内，两次查询 <strong>结果行数</strong> 不同</td> <td>数据被新增</td> <td>⭐ 较轻</td> </tr> </tbody> </table> <p><strong>一句话总结</strong> ：脏读是读了未提交的数据；不可重复读是同一条数据变了；幻读是结果集行数变了。</p> <H2>深度解析</H2> <H3>一、三种问题详解</H3>   <p>上图展示了脏读的发生过程：</p> <ul> <li><strong>时间点 T3</strong> ：事务 B 将 <code>id=1</code> 的 <code>age</code> 从 20 改为 25，但尚未提交</li> <li><strong>时间点 T4</strong> ：事务 A 读取该行数据，得到 <code>age=25</code></li> <li><strong>时间点 T5</strong> ：事务 B 回滚了，数据恢复为 20</li> <li><strong>问题</strong> ：事务 A 读到的 <code>age=25</code> 是 "脏数据"，因为事务 B 根本没提交</li> </ul> <p><strong>脏读危害</strong> ：基于未提交数据做业务判断，可能导致严重的逻辑错误。</p>   <p>上图展示了不可重复读的发生过程：</p> <ul> <li><strong>时间点 T2</strong> ：事务 A 第一次读取， <code>age=20</code></li> <li><strong>时间点 T4~T5</strong> ：事务 B 修改了这条数据并提交</li> <li><strong>时间点 T6</strong> ：事务 A 再次读取同一行， <code>age=25</code></li> <li><strong>问题</strong> ：同一事务内，两次读取同一数据，结果不一致</li> </ul> <p><strong>与脏读的区别</strong> ：不可重复读读到的是 <strong>已提交</strong> 的数据，不是脏数据。</p>   <p>上图展示了幻读的发生过程：</p> <ul> <li><strong>时间点 T2</strong> ：事务 A 查询 <code>age &gt; 20</code> 的记录，返回 2 条</li> <li><strong>时间点 T4~T5</strong> ：事务 B 新增了一条 <code>age=30</code> 的记录并提交</li> <li><strong>时间点 T6</strong> ：事务 A 再次用相同条件查询，返回 3 条</li> <li><strong>问题</strong> ：同一事务内，两次相同查询，结果行数不同，仿佛出现了 "幻影"</li> </ul> <p><strong>与不可重复读的区别</strong> ：</p> <ul> <li>不可重复读强调 <strong>同一条数据被修改</strong> （UPDATE/DELETE）</li> <li>幻读强调 <strong>结果集行数变化</strong> （INSERT/DELETE）</li> </ul> <H3>二、四种隔离级别</H3>   <p><strong>隔离级别详解</strong> ：</p> <ol> <li> <p><strong>READ UNCOMMITTED（读未提交）</strong></p> <ul> <li>最低隔离级别</li> <li>可能发生脏读、不可重复读、幻读</li> <li>几乎不使用</li> </ul> </li> <li> <p><strong>READ COMMITTED（读已提交，RC）</strong></p> <ul> <li>只能读取已提交的数据</li> <li>解决了脏读，但可能发生不可重复读、幻读</li> <li>Oracle、SQL Server 默认级别</li> </ul> </li> <li> <p><strong>REPEATABLE READ（可重复读，RR）</strong></p> <ul> <li><strong>MySQL InnoDB 默认隔离级别</strong></li> <li>保证同一事务内多次读取同一数据结果一致</li> <li>解决了脏读、不可重复读</li> <li>InnoDB 通过 <strong>MVCC + Next-Key Lock</strong> 也解决了幻读</li> </ul> </li> <li> <p><strong>SERIALIZABLE（串行化）</strong></p> <ul> <li>最高隔离级别</li> <li>强制事务串行执行</li> <li>解决所有问题，但性能最差</li> </ul> </li> </ol> <H3>三、MySQL 如何解决这些问题</H3>   <p><strong>MVCC 解决不可重复读</strong> ：</p> <pre><code class="language-sql" data-lang="sql">-- RR 级别下，MVCC 保证可重复读
-- 事务 A
BEGIN;
SELECT * FROM users WHERE id = 1;  -- age=20，生成 Read View

-- 此时事务 B 修改并提交
-- UPDATE users SET age=25 WHERE id=1; COMMIT;

SELECT * FROM users WHERE id = 1;  -- 仍然读到 age=20
-- 因为 MVCC 根据事务 A 的 Read View，只能看到历史版本
COMMIT;</code></pre> <p><strong>Next-Key Lock 解决幻读</strong> ：</p> <pre><code class="language-sql" data-lang="sql">-- RR 级别下，当前读使用 Next-Key Lock
-- 事务 A
BEGIN;
SELECT * FROM users WHERE age &gt; 20 FOR UPDATE;
-- 锁定 age &gt; 20 的所有行，以及 (20, +∞) 的间隙

-- 此时事务 B 尝试插入
-- INSERT INTO users(age) VALUES(30);  -- 被阻塞！

COMMIT;  -- 事务 A 提交后，事务 B 才能插入</code></pre> <H3>四、对比总结</H3>   <H2>面试高频追问</H2> <ol> <li> <p><strong>MySQL 默认隔离级别是什么？如何解决幻读？</strong></p> <ul> <li>默认是 <code>REPEATABLE READ</code> （可重复读）</li> <li>通过 <strong>MVCC</strong> 解决快照读的幻读</li> <li>通过 <strong>Next-Key Lock</strong> （行锁 + 间隙锁）解决当前读的幻读</li> </ul> </li> <li> <p><strong>RC 和 RR 的区别？</strong></p> <ul> <li><code>RC</code> ：每次 <code>SELECT</code> 生成新的 <code>Read View</code> ，能看到其他事务已提交的修改</li> <li><code>RR</code> ：第一次 <code>SELECT</code> 生成 <code>Read View</code> ，后续复用，保证可重复读</li> </ul> </li> <li> <p><strong>什么是 MVCC？</strong></p> <ul> <li>多版本并发控制，每行数据保存版本链（通过 <code>undo log</code> ）</li> <li>读操作根据 <code>Read View</code> 判断哪个版本对自己可见</li> <li>实现 "读不阻塞写，写不阻塞读"</li> </ul> </li> <li> <p><strong>什么时候用 SERIALIZABLE？</strong></p> <ul> <li>需要严格数据一致性的场景（如金融交易）</li> <li>一般不推荐使用，性能太差</li> </ul> </li> </ol> <H2>常见面试变体</H2> <ul> <li>"MySQL 有哪些事务隔离级别？"</li> <li>"RR 级别能完全解决幻读吗？"</li> <li>"MVCC 是怎么实现的？"</li> <li>"什么是 Next-Key Lock？"</li> </ul> <H2>记忆口诀</H2> <p><strong>脏读未提交，数据不可信；</strong> <strong>不可重复读，同条数据变；</strong> <strong>幻读多或少，结果行数变。</strong> <strong>RC 解脏读，RR 解后俩，串行全解决。</strong></p> <H2>总结</H2> <p>脏读是读到未提交的数据（最严重）；不可重复读是同一事务内同一行数据变了（UPDATE/DELETE）；幻读是同一事务内查询结果行数变了（INSERT/DELETE）。MySQL 默认使用 <code>REPEATABLE READ</code> 隔离级别，通过 <strong>MVCC</strong> 解决不可重复读，通过 <strong>MVCC + Next-Key Lock</strong> 解决幻读。</p> </div></main>
