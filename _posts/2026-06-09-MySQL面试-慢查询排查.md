## 深度解析

### 一、开启慢查询日志

```sql
-- 1. 查看慢查询日志配?
SHOW VARIABLES LIKE '%slow_query%';
-- slow_query_log: OFF/ON（是否开启）
-- slow_query_log_file: 慢查询日志文件路?

-- 2. 查看慢查询阈值（默认 10 秒）
SHOW VARIABLES LIKE 'long_query_time';

-- 3. 动态开启慢查询日志（重启失效）
SET GLOBAL slow_query_log = ON;
SET GLOBAL long_query_time = 1;  -- 设置?1 ?

-- 4. 是否记录没走索引?SQL
SHOW VARIABLES LIKE 'log_queries_not_using_indexes';
SET GLOBAL log_queries_not_using_indexes = ON;
```

**配置文件方式（永久生效）**?

```ini
# my.cnf
[mysqld]
slow_query_log = ON
slow_query_log_file = /var/log/mysql/slow.log
long_query_time = 1
log_queries_not_using_indexes = ON
```

**关键参数说明**?

- `slow_query_log`：是否开启慢查询日志
- `long_query_time`：慢查询阈值，超过该时间的 SQL 会被记录（单位：秒，可精确到微秒?
- `log_queries_not_using_indexes`：是否记录没走索引的 SQL（即使很快）
- `min_examined_row_limit`：扫描行数少于此值不记录（避免记录简单查询）

    query_id,
    LEFT(query, 100) AS query_preview,
    exec_count,
    avg_latency / 1000000 AS avg_ms,
    rows_examined,
    rows_sent

### 四、常见慢查询场景与优?

![](https://aka.doubaocdn.com/s/EREG1wZNox)

**优化实战示例**?

```sql
-- 优化前：全表扫描 + 文件排序
EXPLAIN SELECT * FROM orders
WHERE status = 1 ORDER BY create_time DESC LIMIT 100;
-- type: ALL, Extra: Using where; Using filesort

-- 优化：添加联合索?
CREATE INDEX idx_status_create_time ON orders(status, create_time);

-- 优化后：索引范围扫描 + 索引排序
-- type: ref, Extra: Using index condition
```

```sql
-- 优化前：索引失效（函数操作）
EXPLAIN SELECT * FROM orders
WHERE YEAR(create_time) = 2024;
-- type: ALL（索引失效！?

-- 优化后：改写为范围查?
EXPLAIN SELECT * FROM orders
WHERE create_time >= '2024-01-01'
  AND create_time < '2025-01-01';
-- type: range, key: idx_create_time
```

## 面试高频追问

1. **EXPLAIN ?type 有哪些类型？从好到差排序?*
    - `system` > `const` > `eq_ref` > `ref` > `range` > `index` > `ALL`
    - 看到 `ALL` 必须优化（全表扫描）

2. **什么情况会导致索引失效?*
    - `LIKE` 左模糊：`WHERE name LIKE '%abc'`
    - 对索引列使用函数：`WHERE YEAR(create_time) = 2024`
    - 隐式类型转换：`phone` ?VARCHAR，但 `WHERE phone = 13800138000`
    - `OR` 条件中有非索引列
    - `!=`、`<>`、`NOT IN`（不一定，看优化器?
    - 联合索引不满足最左前缀

3. **什么是覆盖索引？有什么好处？**
    - 查询的列都在索引中，不需要回表查聚簇索引
    - `EXPLAIN` ?`Extra` 显示 `Using index`
    - 减少一?B+Tree 查找，降?I/O

4. **如何优化深分页问题？**

```sql
-- 优化前：越往后越?
SELECT * FROM orders LIMIT 1000000, 10;

-- 优化后：使用子查?+ 覆盖索引
SELECT * FROM orders a
JOIN (SELECT id FROM orders LIMIT 1000000, 10) b
ON a.id = b.id;
```
