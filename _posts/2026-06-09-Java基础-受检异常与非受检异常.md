<li><strong><code>Throwable</code></strong> ：所有异常的父类，只有它的子类才能被 <code>throw</code> 或 <code>catch</code></li> <li><strong><code>Error</code></strong> ：JVM 级别的严重错误，程序无法恢复（如 <code>OutOfMemoryError</code> 、 <code>StackOverflowError</code> ）</li> <li><strong><code>Exception</code></strong> ：程序可以处理的异常 <ul> <li><strong>受检异常</strong> ： <code>IOException</code> 、 <code>SQLException</code> 等，编译器强制处理</li> <li><strong>非受检异常</strong> ： <code>RuntimeException</code> 及其子类，编译器不强制处理</li> </ul> </li> </ul> <H3>二、受检异常 vs 非受检异常</H3> <pre><code class="language-java" data-lang="java">import java.io.*;

public class ExceptionDemo {

    // ========== 受检异常：必须处理 ==========
    public void readCheckedFile(String path) {
        // ❌ 编译错误：Unhandled exception type IOException
        // FileReader reader = new FileReader(path);

        // ✅ 方式一：try-catch 捕获
        try {
            FileReader reader = new FileReader(path);
        } catch (IOException e) {
            e.printStackTrace();
        }
    }

    // ✅ 方式二：throws 声明抛出
    public void readFile(String path) throws IOException {
        FileReader reader = new FileReader(path);
    }

    // ========== 非受检异常：不强制处理 ==========
    public void uncheckedDemo() {
        String str = null;

        // ⚠️ 编译通过，但运行时抛出 NullPointerException
        System.out.println(str.length());

        // 可以选择捕获，也可以不捕获
        try {
            System.out.println(str.length());
        } catch (NullPointerException e) {
            System.out.println("空指针异常");
        }
    }
}</code></pre> <H3>三、常见异常类型</H3> <table> <thead> <tr> <th>类型</th> <th>异常类</th> <th>触发场景</th> </tr> </thead> <tbody> <tr> <td><strong>Error（非受检）</strong></td> <td><code>OutOfMemoryError</code></td> <td>内存不足</td> </tr> <tr> <td></td> <td><code>StackOverflowError</code></td> <td>栈溢出（无限递归）</td> </tr> <tr> <td></td> <td><code>NoClassDefFoundError</code></td> <td>类找不到</td> </tr> <tr> <td><strong>RuntimeException（非受检）</strong></td> <td><code>NullPointerException</code></td> <td>访问 <code>null</code> 对象</td> </tr> <tr> <td></td> <td><code>ArrayIndexOutOfBoundsException</code></td> <td>数组越界</td> </tr> <tr> <td></td> <td><code>ClassCastException</code></td> <td>类型转换失败</td> </tr> <tr> <td></td> <td><code>ArithmeticException</code></td> <td>算术异常（如除零）</td> </tr> <tr> <td></td> <td><code>IllegalArgumentException</code></td> <td>非法参数</td> </tr> <tr> <td><strong>受检异常</strong></td> <td><code>IOException</code></td> <td>IO 操作失败</td> </tr> <tr> <td></td> <td><code>SQLException</code></td> <td>数据库操作失败</td> </tr> <tr> <td></td> <td><code>ClassNotFoundException</code></td> <td>类加载失败</td> </tr> <tr> <td></td> <td><code>InterruptedException</code></td> <td>线程中断</td> </tr> </tbody> </table> <H3>四、如何选择异常类型？</H3>   <p>上图展示了选择异常类型的决策流程。关键原则：</p> <ul> <li><strong>受检异常</strong> ：调用者可以合理恢复的情况（如文件不存在、网络超时）</li> <li><strong>非受检异常</strong> ：程序 bug 或调用者无法处理的情况（如空指针、数组越界）</li> <li><strong>Error</strong> ：JVM 级别的严重问题，程序不应尝试捕获</li> </ul> <H3>五、最佳实践</H3> <pre><code class="language-java" data-lang="java">// ✅ 好的做法：自定义业务异常（继承 RuntimeException）
public class BusinessException extends RuntimeException {
    private String errorCode;

    public BusinessException(String errorCode, String message) {
        super(message);
        this.errorCode = errorCode;
    }
}

// ✅ 好的做法：受检异常转非受检异常（避免污染方法签名）
public void processFile(String path) {
    try {
        readFile(path);
    } catch (IOException e) {
        // 将受检异常包装为非受检异常
        throw new RuntimeException("文件处理失败", e);
    }
}

// ❌ 不好的做法：捕获异常后不处理（吞掉异常）
try {
    doSomething();
} catch (Exception e) {
    // 什么都不做，异常被吞掉了！
}

// ✅ 好的做法：至少记录日志
try {
    doSomething();
} catch (Exception e) {
    log.error("操作失败", e);
    throw new BusinessException("OPERATION_FAILED", "操作失败");
}</code></pre> <H2>面试高频追问</H2> <ol> <li> <p><strong><code>throw</code> 和 <code>throws</code> 有什么区别？</strong></p> <table> <thead> <tr> <th>关键字</th> <th>位置</th> <th>作用</th> </tr> </thead> <tbody> <tr> <td><code>throw</code></td> <td>方法体内</td> <td>抛出一个异常对象</td> </tr> <tr> <td><code>throws</code></td> <td>方法签名上</td> <td>声明方法可能抛出的异常类型</td> </tr> </tbody> </table> </li> <li> <p><strong><code>final</code> 、 <code>finally</code> 、 <code>finalize</code> 有什么区别？</strong></p> <ul> <li><code>final</code> ：修饰符，类不能继承、方法不能重写、变量不能修改</li> <li><code>finally</code> ： <code>try-catch</code> 的最后一块，无论是否异常都会执行</li> <li><code>finalize</code> ： <code>Object</code> 的方法，GC 回收对象前调用（已废弃）</li> </ul> </li> <li> <p><strong>为什么要有受检异常？有人说它是 Java 的设计失误，你怎么看？</strong></p> <p>争议点：</p> <ul> <li><strong>支持者</strong> ：强制处理异常，提高代码健壮性</li> <li><strong>反对者</strong> ：导致代码冗余，异常传播污染方法签名，实际中常被滥用</li> <li><strong>趋势</strong> ：现代框架（Spring）倾向于使用非受检异常</li> </ul> </li> </ol> <H2>常见面试变体</H2> <ul> <li>变体一：" <code>Error</code> 和 <code>Exception</code> 有什么区别？"</li> <li>变体二：" <code>RuntimeException</code> 和普通 <code>Exception</code> 有什么区别？"</li> <li>变体三："如何设计一个自定义异常类？"</li> </ul> <H2>记忆口诀</H2> <p><strong>受检异常编译查，必须 try-catch 或 throws；</strong> <strong>非受检异常运行时，不强制处理随缘抓；</strong> <strong>Error 严重难恢复，Exception 可处理。</strong></p> <H2>总结</H2> <p>Java 异常分为受检异常（必须显式处理）和非受检异常（不强制处理）。受检异常适合可恢复的场景，非受检异常适合程序 bug 或无法恢复的场景。实际开发中，推荐使用非受检异常（继承 <code>RuntimeException</code> ）设计业务异常，避免受检异常污染方法签名。</p> </div></main>
