# 并发编程（三）：线程池（L1 收官课）
## 1. 执行流程：四道缓冲闸

![06-01 线程池执行流程]({{ site.baseurl }}/assets/svg/06-01-线程池执行流程.svg)

```
任务到达 execute(task)
   │
   ▼ core < corePoolSize？──是──> 新建核心线程立即执行
   │否
   ▼ workQueue 未满？──是──> 入队等待 FIFO 排队
   │否
   ▼ thread < maxPoolSize？──是──> 新建非核心线程
   │否
   ▼ 执行拒绝策略
```

**设计哲学**：线程是最贵的资源，能不开就不开；队列廉价，能排队就排队。

关键点：
- **无界队列让 max 永远到不了**——`Executors.newFixedThreadPool` 用 `LinkedBlockingQueue`（无界）→ 永远填不满 → 永远不创建非核心线程 → 任务堆队列 OOM
- `Executors.newCachedThreadPool` 反向坑：max=Integer.MAX_VALUE → 任务洪峰创建无尽线程 OOM
- **生产禁用 Executors，必须 `new ThreadPoolExecutor(...)` 显式设七参数**
- 核心线程默认按需创建（`prestartAllCoreThreads()` 预热）

## 2. 七参数

![06-02 线程池七参数与拒绝策略]({{ site.baseurl }}/assets/svg/06-02-线程池七参数与拒绝策略.svg)

| 参数 | 含义 | 推荐设置 |
|---|---|---|
| corePoolSize | 核心线程数 | CPU 密集 N+1 · IO 密集 2N |
| maxPoolSize | 最大线程数 | IO 密集可放大到 N×倍 |
| keepAliveTime | 非核心线程空闲存活 | 60s 起 |
| unit | 时间单位 | TimeUnit.SECONDS |
| workQueue | 任务队列 | ⚠ 必须有界！拒绝无界 |
| threadFactory | 线程工厂 | 命名前缀 + 守护标志 |
| handler | 拒绝策略 | 见下方四种 |

### CPU 密集 vs IO 密集
- CPU 密集（计算）：`core = N+1`（多一个备胎防偶发停顿）
- IO 密集（网关收发/DB 查询/HTTP 调用）：`core = 2N` 起步——线程大多在等 I/O，CPU 占不住
- **网关 Modbus 收发是典型 IO 密集**——socket read 阻塞，CPU 闲置

## 3. 四种拒绝策略

| 策略 | 行为 | 适用 |
|---|---|---|
| AbortPolicy | 抛 RejectedExecutionException | 默认·可感知 |
| CallerRunsPolicy | 调用者线程自己跑 | **反压限流·推荐** |
| DiscardPolicy | 静默丢最新 | 不推荐·隐藏问题 |
| DiscardOldestPolicy | 丢队首（最早） | 老任务过期场景 |

**CallerRunsPolicy 是限流利器**：队列+线程都满时让提交任务的那个线程自己执行——它就不再能提交新任务，天然形成反压。很多限流框架就基于这个思路。`DiscardPolicy` 是雷——静默丢任务，问题被掩盖。

## 4. 网关并发模型 ↔ 线程池

![06-03 网关并发模型与线程池对照]({{ site.baseurl }}/assets/svg/06-03-网关并发模型与线程池对照.svg)

| 网关做法 | 线程池等价 |
|---|---|
| 每设备独立 FIFO + 调度线程 | 每设备一个 core=max=1 单线程池 |
| MIN_REQUEST_INTERVAL = 400ms | 自实现限速器（线程池无此能力） |
| LinkedHashMap 去重重排 | 自定义 workQueue（去重优先） |
| 写后回读确认 | Future.get() / CompletableFuture |
| 怀疑 pollInterval Redis 与 DB 不一致 | 配置项可见性（见第 4 课 JMM） |
| 消息队列溢出治理 | CallerRunsPolicy 反压 |

注：pollInterval 不一致是跨进程（Redis vs DB），**不是 JMM 范畴**——但单进程内的配置项字段（如 ModbusRequestScheduler 内的 intervalMs）跨线程读写必须保证可见性。
