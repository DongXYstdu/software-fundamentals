标准），以及为什么会产生精度丢失。</p> </li> <li> <p><strong>实战经验</strong> ：金额计算是金融系统的核心场景，考察你是否在生产环境中踩过坑，是否知道正确的解决方案。</p> </li> <li> <p><strong>知识广度</strong> ：从浮点数精度问题延伸到 <code>BigDecimal</code> 的使用、数据库字段选择（ <code>DECIMAL</code> vs <code>DOUBLE</code> ）、分布式场景下的金额处理等。</p> </li> </ol> <H2>核心答案</H2> <p><strong>浮点数（ <code>float</code> / <code>double</code> ）不能用于金额计算，核心原因是 IEEE 754 标准的二进制浮点数无法精确表示某些十进制小数，会导致精度丢失和累计误差。</strong></p> <table> <thead> <tr> <th>数据类型</th> <th>存储方式</th> <th>精度问题</th> <th>金额场景</th> </tr> </thead> <tbody> <tr> <td><code>float</code></td> <td>32 位 IEEE 754</td> <td>约 7 位有效数字</td> <td>❌ 禁止使用</td> </tr> <tr> <td><code>double</code></td> <td>64 位 IEEE 754</td> <td>约 15 位有效数字</td> <td>❌ 禁止使用</td> </tr> <tr> <td><code>BigDecimal</code></td> <td>十进制整数 + 标度</td> <td>任意精度</td> <td>✅ <strong>推荐</strong></td> </tr> <tr> <td><code>long</code> （分）</td> <td>64 位整数</td> <td>精确</td> <td>✅ 推荐</td> </tr> </tbody> </table> <H2>深度解析</H2> <H3>一、精度丢失的本质原因</H3> <p>计算机使用 <strong>二进制</strong> 存储数据，而人类习惯使用 <strong>十进制</strong> 表示金额。某些十进制小数（如 <code>0.1</code> ）在二进制中是 <strong>无限循环小数</strong> ，无法精确表示。</p>   <p>上图展示了十进制小数转换为二进制时的无限循环问题。关键点在于：</p> <ul> <li> <p><strong>无法精确表示</strong> ：十进制的 <code>0.1</code> 、 <code>0.2</code> 、 <code>0.3</code> 等常见小数，在二进制中都是无限循环的，计算机只能截断存储。</p> </li> <li> <p><strong>截断即误差</strong> ： <code>double</code> 类型只有 52 位尾数，超出部分被截断，导致存储的值与真实值存在微小差异。</p> </li> <li> <p><strong>误差会放大</strong> ：单次计算误差可能很小（ <code>0.0000000001</code> 级别），但在 <strong>大量累加</strong> 或 <strong>乘除运算</strong> 后，误差会显著放大。</p> </li> </ul> <H3>二、经典翻车案例</H3> <p>来看一个让无数程序员"怀疑人生"的例子：</p> <pre><code class="language-java" data-lang="java">public class FloatMoneyDemo {
    public static void main(String[] args) {
        // 案例 1：0.1 + 0.2 不等于 0.3
        double a = 0.1;
        double b = 0.2;
        System.out.println(a + b);  // 输出: 0.30000000000000004
        System.out.println(a + b == 0.3);  // 输出: false

        // 案例 2：累加误差更恐怖
        double total = 0.0;
        for (int i = 0; i &lt; 10; i++) {
            total += 0.1;
        }
        System.out.println(total);  // 输出: 0.9999999999999999（不是 1.0！）

        // 案例 3：金额计算翻车
        double price = 19.9;
        int count = 3;
        System.out.println(price * count);  // 输出: 59.699999999999996
    }
}</code></pre> <p>想象一下，如果这是银行系统：用户转账 <code>0.1 + 0.2</code> 元，系统记录的却是 <code>0.30000000000000004</code> 元，日终对账时差了 <code>0.00000000000000004</code> 元，数百万笔交易累计下来...财务部会疯的。</p> <H3>三、IEEE 754 存储结构</H3> <p>以 <code>double</code> 为例，64 位存储结构如下：</p>   <p>上图展示了 <code>double</code> 类型的存储结构。核心要点：</p> <ul> <li> <p><strong>52 位尾数限制</strong> ：只能精确表示约 15-16 位十进制数字，超出部分必然截断。</p> </li> <li> <p><strong>二进制小数特点</strong> ：能精确表示的十进制小数只有 <code>0.5</code> 、 <code>0.25</code> 、 <code>0.125</code> 等（分母为 2 的幂次），其他都是近似值。</p> </li> <li> <p><strong>规格化存储</strong> ：隐含的 <code>1.M</code> 中的 <code>1</code> 不存储，实际精度是 53 位。</p> </li> </ul> <H3>四、正确姿势：BigDecimal</H3> <pre><code class="language-java" data-lang="java">import java.math.BigDecimal;
import java.math.RoundingMode;

public class BigDecimalMoneyDemo {
    public static void main(String[] args) {
        // ⚠️ 错误：用 double 构造 BigDecimal，精度已经丢失
        BigDecimal wrong = new BigDecimal(0.1);
        System.out.println(wrong);  // 输出: 0.1000000000000000055511151231257827021181583404541015625

        // ✅ 正确：用字符串构造 BigDecimal
        BigDecimal a = new BigDecimal("0.1");
        BigDecimal b = new BigDecimal("0.2");
        BigDecimal result = a.add(b);
        System.out.println(result);  // 输出: 0.3
        System.out.println(result.compareTo(new BigDecimal("0.3")) == 0);  // 输出: true

        // ✅ 金额计算：指定舍入模式
        BigDecimal price = new BigDecimal("19.9");
        BigDecimal count = new BigDecimal("3");
        BigDecimal total = price.multiply(count).setScale(2, RoundingMode.HALF_UP);
        System.out.println(total);  // 输出: 59.70

        // ✅ 除法必须指定精度和舍入模式
        BigDecimal amount = new BigDecimal("10");
        BigDecimal divisor = new BigDecimal("3");
        BigDecimal quotient = amount.divide(divisor, 2, RoundingMode.HALF_UP);
        System.out.println(quotient);  // 输出: 3.33
    }
}</code></pre> <p><strong><code>BigDecimal</code> 使用要点</strong> ：</p> <table> <thead> <tr> <th>要点</th> <th>说明</th> </tr> </thead> <tbody> <tr> <td>构造方式</td> <td>必须使用 <strong>字符串构造</strong> <code>new BigDecimal("0.1")</code> ，禁止使用 <code>new BigDecimal(0.1)</code></td> </tr> <tr> <td>比较方式</td> <td>使用 <code>compareTo()</code> 而非 <code>equals()</code> （ <code>equals</code> 会比较精度）</td> </tr> <tr> <td>除法运算</td> <td>必须指定精度和舍入模式，否则可能抛出 <code>ArithmeticException</code></td> </tr> <tr> <td>舍入模式</td> <td>金额通常使用 <code>RoundingMode.HALF_UP</code> （四舍五入）</td> </tr> </tbody> </table> <H3>五、另一种方案：整数存储（分）</H3> <pre><code class="language-java" data-lang="java">public class LongMoneyDemo {
    public static void main(String[] args) {
        // 金额以"分"为单位，使用 long 存储
        long priceInCents = 1990;  // 19.90 元 = 1990 分
        int count = 3;

        long totalInCents = priceInCents * count;  // 5970 分
        double totalInYuan = totalInCents / 100.0;  // 59.70 元（仅用于展示）

        System.out.println("总价（分）: " + totalInCents);      // 输出: 5970
        System.out.println("总价（元）: " + totalInYuan);       // 输出: 59.7
    }
}</code></pre> <p><strong>整数存储方案优势</strong> ：</p> <ul> <li><strong>性能更高</strong> ：整数运算比 <code>BigDecimal</code> 快得多</li> <li><strong>内存更省</strong> ： <code>long</code> 占 8 字节， <code>BigDecimal</code> 对象开销大</li> <li><strong>完全精确</strong> ：整数运算不会丢失精度</li> </ul> <p><strong>适用场景</strong> ：对性能要求高、金额精度固定（精确到分）、不需要复杂运算的场景。</p> <H2>面试高频追问</H2> <ol> <li> <p><strong><code>BigDecimal</code> 的 <code>equals()</code> 和 <code>compareTo()</code> 有什么区别？</strong></p> <p><code>equals()</code> 会比较精度（scale）， <code>new BigDecimal("1.0").equals(new BigDecimal("1.00"))</code> 返回 <code>false</code> ；而 <code>compareTo()</code> 只比较数值大小，返回 <code>0</code> 。金额比较必须用 <code>compareTo()</code> 。</p> </li> <li> <p><strong>数据库中金额字段应该用什么类型？</strong></p> <p>MySQL 使用 <code>DECIMAL(19,4)</code> 或 <code>BIGINT</code> （存分）， <strong>禁止使用 <code>FLOAT</code> / <code>DOUBLE</code></strong> 。 <code>DECIMAL</code> 在数据库层面保证精度， <code>BIGINT</code> 性能更好。</p> </li> <li> <p><strong>分布式场景下金额计算有什么注意事项？</strong></p> <p>多服务并发扣款时，要考虑分布式锁、数据库事务、幂等性，确保金额一致性。可参考 TCC、Saga 等分布式事务方案。</p> </li> </ol> <H2>常见面试变体</H2> <ul> <li>变体一：" <code>0.1 + 0.2 != 0.3</code> 是什么原因？如何解决？"</li> <li>变体二：" <code>BigDecimal</code> 构造时为什么要用字符串？"</li> <li>变体三："金融系统中金额字段如何设计？"</li> </ul> <H2>记忆口诀</H2> <p><strong>浮点存金额，精度必丢失；</strong> <strong>BigD 用字符串，除法指定舍；</strong> <strong>或者用长整，单位换成分。</strong></p> <H2>总结</H2> <p>浮点数采用 IEEE 754 二进制存储，无法精确表示某些十进制小数，金额计算必须使用 <code>BigDecimal</code> （字符串构造）或将金额转为整数（分）存储。数据库中金额字段使用 <code>DECIMAL</code> 或 <code>BIGINT</code> ， <strong>禁止使用 <code>FLOAT</code> / <code>DOUBLE</code></strong> 。</p> </div></main>
