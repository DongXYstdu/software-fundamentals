## 1. 运行时内存结构（JDK 8+）

![01-01 JVM 运行时内存结构]({{ site.baseurl }}/assets/svg/01-01-JVM运行时内存结构.svg)

```
┌──────────────────────── JVM 进程（-Xmx 只管堆）────────────────────────┐
│  ┌──────────── Java 堆 · 线程共享 · GC 主战场 ─────────────┐  ┌─ 线程私有 ─┐ │
│  │  ┌── Eden ──────┐ ┌ Survivor 0 ┐ ┌ Survivor 1 ┐      │  │  虚拟机栈   │ │
│  │  │  新对象出生地  │ │   复制存活   │ │  age 计数   │      │  │ 栈帧·局部   │ │
│  │  └───────────────┘ └─────────────┘ └────────────┘      │  │ 变量表     │ │
│  │  ┌────────────── 老年代 Old ────────────────────┐     │  ├───────────┤ │
│  │  │   长期对象 · 大对象直入 · Full GC 主区        │     │  │ 程序计数器  │ │
│  │  └─────────────────────────────────────────────┘     │  ├───────────┤ │
│  └───────────────────────────────────────────────────────┘  │ 本地方法栈  │ │
│  ┌── Metaspace 元空间 ────────────────────────────────┐    └───────────┘ │
│  │  类元数据 · 本地内存 · 不受 -Xmx 限制               │                  │
│  └────────────────────────────────────────────────────┘  ┌ 直接内存 ──┐ │
│                                                            │NIO Direct- │ │
│                                                            │Buffer·Netty│ │
│                                                            └────────────┘ │
└────────────────────────────────────────────────────────────────────────┘
```

| 区域 | 放什么 | 满了会怎样 | 关键参数 |
|---|---|---|---|
| Eden + Survivor（新生代） | 短命对象：请求、DTO、日志字符串 | Minor GC（几 ms，无感） | `-Xmn`（G1 下别手动设） |
| 老年代 | 长期对象：缓存、连接、大集合 | **Full GC（百 ms~秒级，接口超时）** | `-Xms` `-Xmx` |
| Metaspace | 类元数据（每个类一份） | 类加载泄漏时 Full GC | `-XX:MetaspaceSize` |
| 直接内存 | Netty 的 DirectBuffer | OOM 但 heap dump 看不出来 | `-XX:MaxDirectMemorySize` |

**注意**：Vert.x / Netty 的收发缓冲走直接内存（堆外），网关内存涨但 heap dump "查无此物"时，第一反应查 DirectBuffer。

## 2. GC 分代流转：一个对象的一生

![01-02 GC 分代流转与触发]({{ site.baseurl }}/assets/svg/01-02-GC分代流转与触发.svg)

```
新对象 ──分配──> Eden ──Minor GC·复制存活──> Survivor S0/S1 ──age≥15──> 老年代 Old
                  │                                                  │
                  ▼ Eden 满                                          ▼ Old/Metaspace 满
              [ Minor GC ]                                    [ Full GC ]
              停顿：几~几十 ms                                  停顿：百 ms~秒级
```

- Full GC 其他触发：`System.gc()` · 空间分配担保失败 · Metaspace 动态扩容
- G1 已无固定分代边界：Region 化回收，目标停顿可设（`-XX:MaxGCPauseMillis`）

**核心推论**：调优的本质 = 让对象"生得快、死得早"，别流到老年代。Minor GC 频繁不可怕；Full GC 频繁才是事故。

## 3. 收集器选型

| 收集器 | 停顿 | 适用场景 | 备注 |
|---|---|---|---|
| Parallel | 秒级（吞吐优先） | 批处理、离线计算 | JDK 8 默认 |
| CMS | 百 ms | — | JDK 14 已移除，不学 |
| **G1** | 10~200ms | 通用，堆 4G+ | **JDK 9+ 默认，首选** |
| ZGC | <1ms | 超大堆、极低延迟 | JDK 17 生产可用 |

## 4. 生产启动参数模板

```bash
java -Xms4g -Xmx4g \
  -XX:+UseG1GC -XX:MaxGCPauseMillis=200 \
  -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=256m \
  -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=D:/logs/dump/ \
  -Xlog:gc*,safepoint:file=D:/logs/gc.log:time,uptime,level,tags:filecount=5,filesize=20m \
  -jar yudao-server.jar
```

- `-Xms = -Xmx`：堆恒定，避免伸缩抖动
- `MetaspaceSize = MaxMetaspaceSize`：防动态扩容触发 Full GC
- GC 日志用 `-Xlog:gc*` 直写文件并滚动，**不依赖 stdout**（关键日志永远走文件，不走控制台）

## 5. 排查决策树

![01-03 GC 问题排查决策树]({{ site.baseurl }}/assets/svg/01-03-GC问题排查决策树.svg)

```
                      ┌── CPU 100% 飙高 ──> jstack 连抓两次对比 → 死循环/锁
                      │                     GC 线程忙 → jstat 查堆与分配速率
                      ├── 接口间歇超时 ──> GC 日志看停顿 + jstat -gcutil
                      │                     FGC 高 → 泄漏或堆小；停顿长 → 调参
生产 JVM 异常 ────────┼── OOM 进程退出 ──> HeapDumpOnOOM → hprof → MAT 支配树
                      │                     定位大对象/缓存
                      └── 频繁 Full GC ──> jstat 每 1s 连测看 O 区回收效果
                                            调 Xmx / MaxMetaspace / 换收集器
```

## 6. 工具速查

| 工具 | 用途 | 关键命令 |
|---|---|---|
| `jps` | 找 Java 进程 pid | `jps -l` |
| `jstat` | GC 实时监控（O 区/FGC 次数） | `jstat -gcutil <pid> 1000` |
| `jstack` | 线程栈快照（死循环/锁） | `jstack <pid> > stack.txt` |
| `jmap` | 堆快照/对象直方图 | `jmap -dump:format=b,file=heap.hprof <pid>` |
| Arthas | 生产一体化排查，免装 | `dashboard` / `thread` / `heapdump` |
| GCeasy | GC 日志在线分析 | 拖 gc.log 上传出报告 |

Windows 生产：任务管理器看线程 → Arthas `dashboard` / `thread` / `heapdump` 一把梭。

## 7. 生产场景对照

| 场景 | 对应知识点 |
|---|---|
| bat 启动 stdout 缓冲、日志不打印 | GC 日志 `-Xlog:gc*` 直写文件并滚动，绕开控制台 |
| Modbus 高频轮询 | 分配速率高 → Minor GC 频繁是正常；警惕存活对象多、晋升过快灌满老年代 |
| application-prod 抑制高频日志 | 日志字符串拼装是分配大户，日志降频就是给 GC 降压 |
| Vert.x 网关内存上涨 | Netty DirectBuffer 在堆外，查 `-XX:MaxDirectMemorySize` |
