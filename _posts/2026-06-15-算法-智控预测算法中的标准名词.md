## 预测算法中的标准名词

在 IoT 预测场景（如空压机总管流量预测、设备负载预测）中，我们常常会遇到一系列专业术语。对于后端 / Java 开发者来说，直接啃机器学习教材门槛较高。本文用 **Java 开发中的概念做类比**，帮助快速理解这些"标准名词"到底在说什么、为什么重要。

---

## 一、数据与特征工程类

**1. 自回归特征**

- **是什么**：用目标变量自己过去的值来预测未来。比如用过去 6 个小时的总管流量，预测下一小时的总管流量。
- **Java 类比**：就像你在计算某个接口 QPS 的趋势时，用最近几个时间窗口的 QPS 值作为参考，而不是只看当前值。

**2. 滑动窗口**

- **是什么**：把一条长序列，切成很多固定长度的连续小段，每一段作为一条样本。比如窗口长度 60 分钟，每隔 1 分钟取一次，就会产生大量样本。
- **Java 类比**：类似分页查询，但这里的"页"不是一次性查完，而是每挪一条记录就产生新的一页；或者更直观地，好比 `List.subList(i, i+60)`，i 每次加 1，直到末尾。

**3. 多变量序列**

- **是什么**：不止用气量一种数据，而是多条时间线同时输入模型，比如流量、压力、功率等，形成一张"多列时间表"。
- **Java 类比**：相当于数据库里的一张宽表，时间戳是主键，每一列是一个测点的值，模型一次性读取多列。

**4. 衍生特征 / 特征工程**

- **是什么**：基于原始表计数据，通过计算创造出新的、更有信息量的字段。例如从压力和流量算出**压力变化率**、**空压机加载比例**等。
- **Java 类比**：就像你在 Service 层对 DO 对象做转换，生成 VO 中额外的计算字段，如"订单总金额 = 单价 × 数量"。这里只是把公式换成"△P / △t"。

**5. 滞后关系 / 先行指标**

- **是什么**：一个变量的变化规律性地领先于另一个变量。比如空压机电功率上升，总管流量延迟几秒才跟上，这个延迟就是滞后。
- **为什么重要**：LSTM 就能捕获这种"你动了我等一下才动"的模式，从而用功率提前预测流量。
- **Java 类比**：类似消息队列中的消费延迟，生产者先发消息，消费者过一会儿才处理，通过对齐时间戳可以还原这种因果关系。

**6. 归一化（Normalization）**

- **是什么**：把所有不同量纲的数据（压力是 0-10 bar，流量是 0-1000 m³/h）缩放到一个小的区间（如 0-1 或 -1 到 1），防止大数值特征"淹没"小数值特征。
- **Java 类比**：好比把不同精度的 `BigDecimal` 统一 `scale` 后再计算，或者把枚举值映射成统一的百分比权重，让它们在同一尺度上比较。

## 二、模型训练与样本组织类

**7. 训练集 / 验证集 / 测试集（时序切分）**

- **是什么**：把数据按时间顺序切三段。训练集用来学习，验证集用来调超参和决定何时停止训练，测试集用来最终评估效果。
- **关键**：时序数据**不能随机打乱**，必须保证测试集时间晚于训练集，否则就是"用未来预测过去"。
- **Java 类比**：类似单元测试的 Before/After 顺序，如果你用将来的配置测试过去的代码，那就是作弊。测试环境必须严格隔离。

**8. 数据泄露**

- **是什么**：训练时不小心把测试集的信息（如测试集的均值、最大值）用到了归一化或特征构造中，导致模型在测试时表现虚高。
- **Java 类比**：就像在联调时把生产库的数据导入了测试环境，结果测试全绿，一上线就崩。

**9. 早停（Early Stopping）**

- **是什么**：训练过程中，每轮结束后看在验证集上的误差，如果连续 N 轮误差不再下降，就提前终止训练，防止过拟合。
- **Java 类比**：类似超时熔断，当连续错误达到阈值，就直接切断请求，不继续浪费资源。

**10. 超参调优**

- **是什么**：调整那些不是模型从数据中学习到的参数，比如滑动窗口长度、LSTM 层数、隐藏单元数、学习率等。
- **Java 类比**：就像调 JVM 参数（堆大小、GC 策略），或是数据库连接池大小，需要根据性能测试结果反复试。

**11. 损失函数（MSE / MAE / Huber）**

- **是什么**：衡量预测值与真实值差距的公式。

| 损失函数 | 特点 | 适用场景 |
|----------|------|----------|
| MSE | 放大特大误差（平方），对异常值敏感 | 异常值较少时 |
| MAE | 绝对误差，鲁棒 | 存在异常值时 |
| Huber | 结合两者，误差小时用平方，大时用线性 | 兼顾两者优点 |

- **Java 类比**：类似你定义异常处理策略，是直接抛异常、记日志还是降级返回，取决于你对某些错误有多不能容忍。

**12. 批大小（Batch Size）**

- **是什么**：每次喂给模型训练的一小批样本的数量，不是一次读全部数据。
- **Java 类比**：类似 JDBC 分页读取或消息队列的批量 consume，避免内存溢出。

## 三、评估与部署类

**13. 回测（Backtesting）**

- **是什么**：用历史数据模拟实时预测的过程，看模型在"过去某个时间点"的预测效果，就像穿越回去验证。
- **Java 类比**：类似用历史日志重放来验证告警规则是否有效，或者回放线上流量到测试环境做压测。

**14. 概念漂移（Concept Drift）**

- **是什么**：数据的内在规律随时间变化了，比如空压机换新、生产工艺改变，导致老模型不准。
- **Java 类比**：线上业务规则改了，但你的代码缓存没更新，需要刷新缓存并可能重新上线服务。

**15. 残差 / 系统性偏差**

- **是什么**：残差 = 真实值 - 预测值。如果残差总往一个方向偏（比如总是低估峰值），就是系统性偏差，说明模型有问题。
- **Java 类比**：类似你的接口日志里，某个错误码的比例总是异常高，说明不是偶发 bug，而是处理逻辑有缺陷。

**16. 缺失值插补与前向填充**

- **是什么**：采集点偶尔断连，数据出现空窗。前向填充就是把上一个有效值填充到空窗里；线性插值则是按前后时间点算个中间值。
- **Java 类比**：类似你从 Redis 取缓存，如果没有就查库，再没有就用默认值（前向填充），或者根据上下文计算一个近似值（插值）。

**17. 产气响应延迟 / 缓冲时间**

- **是什么**：从用气端突然加大用量，到空压机感知到压力下降并开始加载产气，再到储气罐把气送出去，中间存在物理延迟。这就是你在设计窗口长度时必须覆盖的时间段。
- **Java 类比**：类似一个 API 调用链路中的总耗时，包含网络 RTT、业务处理、数据库查询，窗口长度要能"装下"这个完整链路，模型才能学习到完整因果。

---

## 四、总结

本文梳理了预测算法中 17 个核心标准名词，分为三大类：

| 类别 | 涵盖名词 |
|------|----------|
| 数据与特征工程 | 自回归特征、滑动窗口、多变量序列、衍生特征、滞后关系、归一化 |
| 模型训练与样本组织 | 训练/验证/测试集切分、数据泄露、早停、超参调优、损失函数、批大小 |
| 评估与部署 | 回测、概念漂移、残差分析、缺失值插补、响应延迟 |

记住一个核心原则：**预测模型的每一个概念，在 Java 开发中都能找到对应的工程实践**。用熟悉的框架去理解陌生的领域，是最高效的学习方式。
